# Lessons Learned - Bunny Cove Project

## General & Workflow Lessons
- **User Instruction Precision**: When the user requests to initialize folder bases without code, keep the directories clean and empty until explicitly instructed to start implementation. Do not scaffold boilerplate with premature feature logic.
- **Naming Conventions**: Directory names are strictly `mobile` (Flutter) and `server` (NestJS).
- **Communication Language**: All communications, explanations, roadmaps, and plan discussions must be in clear, structured Vietnamese. All source code, comments, and commit messages must be in English.
- **Rules & Specs**: Always follow [AGENTS.md](../AGENTS.md) and [general.md](../general.md) as the single source of truth for architectural and coding standards.
- **Separation of Concerns for AI Customizations (Rules vs Skills)**: Keep rules and skills strictly separated. Global behavioral constraints, coding standards, and zero hard-coding rules must be placed in rules files (`AGENTS.md`) so they are always active. Skills (`.agents/skills/`) must be reserved exclusively for on-demand actionable workflows/procedures (such as `/compact`). Never shoehorn coding rules into skill workflow definitions.
- **Extensible Game Architecture (Plugin/Strategy Pattern)**: Avoid hardcoding game types (e.g., hardcoded enums 'CARO' | 'BINGO' or game-specific gateway event handlers). Use an abstract `IGameEngine` interface and a dynamic `GameRegistry` so that new games can be added effortlessly without modifying core Room or Gateway code.
- **Prisma 7 Driver Adapter & Config**: Prisma 7 uses `prisma.config.ts` with `datasource: { url: ... }` (singular) and requires driver adapters like `@prisma/adapter-pg` + `pg` rather than the old Rust query engine. Always import `dotenv/config` so CLI commands can resolve environment variables.
- **Cloud Infrastructure for Restricted Environments**: When developer laptops block local Docker, PostgreSQL, or DBeaver, utilize zero-install Cloud providers: Supabase for PostgreSQL and Upstash for Redis. For Redis, `@upstash/redis` (REST over HTTPS port 443) reliably bypasses local firewall blocks on TCP port 6379.
- **Scalable Multiplayer Schema**: Never hardcode player slots (e.g., `player1Id`, `player2Id`) in match history. Use a junction `MatchParticipant` model with `seatIndex`, `score`, `rank`, and `isWinner` to seamlessly accommodate 1v1, 2v2, 4-player Bingo, or N-player party mini-games.
- **Zero Hard-Coded Defaults & URLs**: Never hard-code default URLs, mock/fallback image URLs, CDN paths, or default assets in services, controllers, or DTOs. Always define them in dedicated constants files under the designated `constants/` directory (e.g. `server/src/common/constants/defaults.ts`).
- **Strict No Auto-Push Protocol**: Never push code automatically. Stage and commit locally, but wait for the user to explicitly invoke `/push`, `/push-dev`, or give a direct push command.
- **Mandatory Persistent Test Flows for APIs**: Never rely on ad-hoc or session-only verification. Every API or WebSocket feature must have a dedicated, persistent test script in `server/test/` (e.g. `verify-[feature]-flow.mjs`) registered into `server/test/verify-all.mjs` (`npm run test:verify`). Before any push, the full test suite must pass 100%.
- **100% English Comments, Configs & Env Files (Strict Rule)**: Never write non-English or Vietnamese comments inside source code, test files, config files, or environment files (`.env`, `.env.example`). Vietnamese is strictly and exclusively reserved for direct conversational explanations and planning with the user in the chat UI.
- **Mobile Architecture Preservation Before Re-Initialization**: Always explicitly preserve and document the exact Feature-Driven Clean Architecture (`common_libs.dart`, `service_locator.dart`, `core/`, `common/`, `features/`) in `AGENTS.md` before performing any cleanup or re-initialization of the mobile client.
- **Error Localization & Response Code Decoupling**: Backend error messages (`error.message`) are exclusively for debugging/logging. The client UI must NEVER render raw unlocalized server error strings to the end user. Frontend (Flutter & Web) must map backend `error.code` to localized text via localization files (`.arb` / `AppLocalizations` on Flutter) based on the user's active locale.
- **Centralized Barrel Import (`common_libs.dart`) Usage**: Always import `package:bunny_cove_app/common_libs.dart` whenever UI, routing, theme, constants (`AppUrlsConstant`, `StorageKeysConstant`, etc.), or common widgets are needed across files, strictly avoiding direct relative imports to individual constant or widget files.
- **Dynamic Environment Resolution in Constants**: `AppUrlsConstant` and related URL definitions must dynamically read from `.env` (`dotenv.env['BASE_URL']`, `dotenv.env['SOCKET_URL']`) rather than using static hard-coded string literals, adhering strictly to the Zero Hard-Coding rule.
- **Centralized Typography & Strict Zero Inline TextStyle**: Never write inline `TextStyle(...)` inside UI widgets, custom components, pages, snackbars, or dialogs. All text styles must strictly consume `Theme.of(context).textTheme.[role]` or static getters from `AppTypography.[role]` (exported via `common_libs.dart`). Any variation in text appearance (such as color or font weight) must be done exclusively using `.copyWith(...)` on existing theme styles.
- **Zero Hardcoded User-Facing Text & Mandatory Localization (l10n)**: Never hardcode raw string literals for user-facing UI labels, descriptions, button text, dialog prompts, form hints, or validation error messages in widgets. Always declare them in `lib/core/config/lang/arb/app_en.arb` and `app_vi.arb`, run `flutter gen-l10n`, and consume them exclusively via `context.l10n.[key]` (exported via `common_libs.dart`). Use ARB placeholders for dynamic values.

- **Consolidated Single Source of Truth (`AGENTS.md`)**: Maintain exactly ONE master rule file (`AGENTS.md`) at the repository root to prevent rule fragmentation and drift. Never split rules into arbitrary `rule.md` or subfolder `AGENTS.md` files; Antigravity natively loads root `AGENTS.md` unconditionally into the system prompt across all sessions.
- **Local Font Registration & Centralized Typography (`Sniglet`)**: Custom fonts stored under `assets/fonts/` must be registered in `pubspec.yaml` under `flutter.fonts` with accurate weight mappings (e.g. `Regular` -> 400, `ExtraBold` -> 800) and set centrally as `AppTypography.fontFamily` on `ThemeData` and throughout `AppTypography.textTheme`.
- **Structured NestJS Exception Envelope**: Always throw NestJS exceptions with a structured payload `{ code: ResponseCodes.xxx, message: '...' }` rather than plain string messages. Plain string exceptions bypass code assignment in filters and fallback to generic server error or unlocalized responses, violating API standards.
- **Clean Architecture Zero Relative Import Principle**: Export essential core classes (`Failure`, `UseCase`, `NoParams`) directly from the centralized barrel (`common_libs.dart`). All feature layers (data, domain, presentation) must exclusively use package imports (`package:bunny_cove_app/...`), entirely eliminating messy deep relative paths (`../../../../core/...`).
- **Continuous Audit Skill (`/recheck`)**: Maintain a specialized on-demand compliance audit skill (`.agents/skills/recheck/SKILL.md`) that codifies all verification gates (zero inline styles, zero hardcoded UI strings, zero non-English comments, synchronized response codes, automated linting & persistent test suites) for ongoing quality enforcement.

- **Resilient Realtime In-Room Chat Architecture**: In WebSocket room systems, client sockets are grouped into room channels. Separating chat into a dedicated ChatGateway and ChatService while leveraging the existing room socket membership allows modularity without coupling room lifecycle to messaging. Message persistence supports optional senderId and roomCode with in-memory fallbacks so guest users or offline databases never disrupt realtime gameplay.
- **Node.js Libuv Socket Teardown on Windows**: When tearing down Socket.IO client connections in automated test scripts on Windows under Node.js, explicit socket disconnection and a brief event-loop flush delay before closing NestApplication prevents libuv async handle assertion crashes.

- **Next.js Web Client 3-Layer Clean Architecture & Thin App Router**: Structure `web/src/` strictly into `domain/` (pure entities & repository interfaces), `application/` (DTOs, mappers, services), `infrastructure/` (implementations, RTK/Zustand, HTTP client), and `presentation/` (pages, components, hooks, providers). Files under `src/app/` (`page.tsx`) must remain ultra-thin entrypoints that merely unpack server-side route parameters and pass them directly to Presentation page components, with zero UI markup or network queries.
- **Web UI & Interaction Standards**: Centralize Light/Dark theme switching through a global `ThemeProvider` and header `ThemeToggle`. Adhere strictly to the "Honey Oak & Sweet Cream" design tokens with CSS variables and Merriweather serif font (`var(--font-merriweather)`) to maintain aesthetic harmony. Apply `cursor-pointer` on all interactive nodes and `select-none` on layouts to provide a clean, native-feeling desktop experience without accidental text highlighting.
- **DTO Payload Permissiveness Across Multi-Platform Clients**: When NestJS backend enforces `forbidNonWhitelisted: true`, mobile or web clients may send optional payload keys (e.g. `email` alongside `identifier`, or optional custom `username` during registration). DTOs must explicitly define optional compatible fields using `@IsOptional()` to prevent accidental HTTP 400 Bad Request errors across heterogeneous client ecosystems.
